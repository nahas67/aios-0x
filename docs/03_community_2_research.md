## 1. Community Purpose & Responsibilities

### 1.1 Primary Objective
Community 2 (C2) serves as the quantitative and thesis generation engine of AIOS. Its primary objective is to transform clean, normalized market events (`MarketDataPayload`) received from Community 1 into structured, multi-perspective investment hypotheses (`CandidateHypothesis`).

### 1.2 Core Responsibilities
- **Multi-Perspective Market Analysis**: Evaluate market trends, sentiment profiles, volume spikes, and statistical anomalies across multiple timeframes.
- **Adversarial Thesis Debate**: Conduct structured debates between specialized Bull, Bear, Quant, and Macro agents to eliminate bias.
- **Balanced Hypothesis Formulation**: Enforce mandatory inclusion of both supporting arguments and explicit counter-arguments for every candidate hypothesis.
- **Risk/Reward Thresholding**: Calculate initial expected risk-to-reward (R:R) ratios based on structural support/resistance levels.
- **Historical Memory Querying**: Interface with Community 7 (Institutional Memory) to verify if similar historical setups previously resulted in strategy failures or regime shifts.
- **Event Dispatching**: Publish vetted hypotheses to `research.hypothesis_generated` (`EventTopic.HYPOTHESIS_GENERATED`).

## 2. Agent Hierarchy & Roles

Community 2 employs an adversarial, multi-agent debate structure coordinated by a Debate Moderator Agent:

```
                               +-----------------------------+
                               |   DEBATE MODERATOR AGENT    |
                               | (Synthesizes Final Thesis)  |
                               +-----------------------------+
                                              ^
               +------------------------------+------------------------------+
               |                              |                              |
               v                              v                              v
+-----------------------------+ +-----------------------------+ +-----------------------------+
|      BULL THESIS AGENT      | |      BEAR THESIS AGENT      | |      QUANT ALPHA AGENT      |
| (Momentum & Positive Flow)  | | (Downside Risks & Squeeze)  | | (Anomalies & Divergences) |
+-----------------------------+ +-----------------------------+ +-----------------------------+
                                              ^
                                              |
                               +-----------------------------+
                               |     MACRO ANALYST AGENT     |
                               | (Macro Regimes & Rates)     |
                               +-----------------------------+
```

### 2.1 Bull Thesis Agent
- **Role**: Advocates for long entries and positive momentum thesis.
- **Focus**: Evaluates upward trendlines, volume confirmation, bullish indicator crossovers, and positive news sentiment scores ($> 0.0$).

### 2.2 Bear Thesis Agent
- **Role**: Acts as the adversarial counter-weight, actively probing for downside catalysts.
- **Focus**: Identifies overhead resistance levels, volume exhaustion, negative sentiment ($< 0.0$), macroeconomic headwinds, and potential liquidity squeezes.

### 2.3 Quant Alpha Agent
- **Role**: Conducts non-discretionary statistical pattern recognition.
- **Focus**: Calculates RSI/MACD divergences, Bollinger Band squeezes, statistical mean-reversion probabilities, and anomaly Z-scores.

### 2.4 Macro Analyst Agent
- **Role**: Contextualizes local asset behavior within top-down global macroeconomic conditions.
- **Focus**: Analyzes Federal Reserve policy rates, CPI/inflation prints, liquidity indices, and broad market regime classification (e.g. Risk-On vs. Risk-Off).

### 2.5 Debate Moderator Agent (`ResearchAgent`)
- **Role**: Orchestrates the multi-agent debate round, collects arguments, enforces counter-argument balance, and formulates the finalized `CandidateHypothesis`.

## 3. Structured Debate & Thesis Formulation Protocol

### 3.1 Multi-Perspective Debate Protocol
Every research hypothesis generated by Community 2 must adhere to strict debate rules:
1. **Mandatory Balance Rule**: A hypothesis CANNOT be published with zero counter-arguments. If the Bull case is overwhelming, the Bear Agent must explicitly articulate failure modes (e.g. false breakout risk, macro liquidity contraction).
2. **Argument Qualification**: All supporting and counter arguments must be supported by empirical observations from `MarketDataPayload` (e.g., price change %, sentiment score, volume ratio).

### 3.2 Risk/Reward Ratio Heuristics
- Expected Risk-to-Reward Ratio ($R:R$) is calculated as:
  $$R:R = \frac{|\text{Target Price} - \text{Entry Price}|}{|\text{Entry Price} - \text{Stop Loss Price}|}$$
- **Minimum R:R Threshold**: $R:R \ge 2.0$. Hypotheses offering an expected $R:R < 2.0$ are rejected during research synthesis.

### 3.3 Historical Memory Lookup Protocol
Before finalizing a thesis, Community 2 queries Community 7 (Memory Architecture):
- **Query**: Vector similarity search over past `CandidateHypothesis` and `ObservationReport` records matching current market features.
- **Memory Check Rule**: If $\ge 70\%$ of similar historical setups resulted in negative realized PnL due to specific recurring traps (e.g. "FOMC announcement whip-saw"), the Debate Moderator adds that historical trap to `counter_arguments`.

## 4. Output Schema & Event Bus Routing

### 4.1 Output Schema Definition
Community 2 outputs instances of `CandidateHypothesis` defined in `schemas/contracts.py`:

```python
class CandidateHypothesis(BaseModel):
    hypothesis_id: str = Field(
        default_factory=generate_uuid, description="Unique UUID string representing this hypothesis"
    )
    created_at: datetime = Field(
        default_factory=generate_utc_now, description="UTC datetime when the hypothesis was created"
    )
    symbol: str = Field(
        ..., min_length=1, description="Trading symbol of the asset (e.g., BTC/USD)"
    )
    thesis: str = Field(
        ..., min_length=1, description="Detailed thesis presenting the Bull/Bear rationale"
    )
    supporting_arguments: list[str] = Field(
        ..., description="List of arguments supporting the thesis"
    )
    counter_arguments: list[str] = Field(
        ..., description="List of arguments warning against or contradicting the thesis"
    )
    timeframe: str = Field(
        ..., min_length=1, description="Timeframe for the expected outcome (e.g., 4h, 1d)"
    )
    expected_risk_reward_ratio: float = Field(
        ..., gt=0.0, description="Target risk to reward ratio (minimum 2.0)"
    )
```

### 4.2 Event Bus Routing
- **Subscription Topic**: `data.acquired` (`EventTopic.DATA_ACQUIRED`) via `on_data_acquired()` callback.
- **Publication Topic**: `research.hypothesis_generated` (`EventTopic.HYPOTHESIS_GENERATED`).
- **Target Subscriber**: Community 3 (Verification Firewall).
